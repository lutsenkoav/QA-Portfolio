# Сценарии тестирования: Модульные представления

## 📌 Цель документа

Описать ключевые бизнес-сценарии использования модульных представлений (ListView, TreeView, View display, View picker) в контексте реальных задач пользователя. Сценарии показывают, как компоненты работают вместе для достижения бизнес-целей.

## Сценарий 1: Просмотр и фильтрация списка документов

**ID:** SCEN-001  
**Приоритет:** High  
**Компоненты:** ListView, View display

### Описание
Пользователь открывает список документов, видит их ключевые атрибуты и может быстро найти нужный документ с помощью фильтрации.

### Предусловия
- Пользователь авторизован в системе.
- В системе создано минимум 20 документов с разными статусами.
- У документов заполнены поля: название, дата создания, статус, тип.

### Основной поток (Happy Path)
| Шаг | Действие пользователя | Ожидаемый результат системы |
|-----|----------------------|----------------------------|
| 1 | Открывает раздел "Документы" | Отображается ListView с документами. В строке каждого документа видны: название, дата, статус (чипс), иконка типа. |
| 2 | Прокручивает список до конца | Автоматически подгружаются следующие страницы (пагинация или бесконечный скролл). |
| 3 | Вводит в поле поиска название документа | Список фильтруется, отображаются только документы, содержащие введённый текст. |
| 4 | Кликает по чекбоксу нужного документа | Документ выделяется. Внизу появляется меню действий. |
| 5 | В меню действий выбирает "Просмотреть" | Открывается карточка документа (View display). |

### Альтернативные потоки
| Сценарий | Действие пользователя | Ожидаемый результат |
|----------|----------------------|---------------------|
| **Пустой список** | Открывает раздел, в котором нет документов | Отображается сообщение "Нет документов для отображения". |
| **Нет результатов поиска** | Вводит в поиск несуществующее название | Отображается сообщение "Ничего не найдено". |
| **Сброс фильтра** | Нажимает кнопку "Очистить фильтр" | Список возвращается к исходному состоянию, отображаются все документы. |

### Связанные тест-кейсы
- TC-ListView-001, TC-ListView-002 (отображение данных)
- TC-ListView-003 (чипсы)
- TC-ListView-016, TC-ListView-017 (пагинация)
- TC-ListView-010, TC-ListView-012 (выделение)
- TC-ViewDisplay-001, TC-ViewDisplay-002 (отображение и переход)

## Сценарий 2: Навигация по иерархии папок

**ID:** SCEN-002  
**Приоритет:** High  
**Компоненты:** TreeView

### Описание
Пользователь работает с иерархической структурой папок и документов, перемещаясь по уровням вложенности для поиска нужного документа.

### Предусловия
- Пользователь авторизован в системе.
- В системе создана структура папок глубиной минимум 3 уровня.
- В папках есть документы (ФИ) и пустые папки.

### Основной поток (Happy Path)
| Шаг | Действие пользователя | Ожидаемый результат системы |
|-----|----------------------|----------------------------|
| 1 | Открывает раздел с деревом папок (TreeView) | Отображаются корневые папки в свернутом виде. Справа от каждой — иконка "развернуть". |
| 2 | Нажимает на иконку "развернуть" у корневой папки | Папка разворачивается, отображаются дочерние папки и документы. Иконка меняется на "свернуть". |
| 3 | Разворачивает вложенную папку | Отображаются элементы следующего уровня. Отступы визуально показывают иерархию. |
| 4 | Кликает по названию документа | Документ выделяется (становится активным). |
| 5 | Дважды кликает по выделенному документу | Открывается форма документа (ФИ) в рабочей области. |

### Альтернативные потоки
| Сценарий | Действие пользователя | Ожидаемый результат |
|----------|----------------------|---------------------|
| **Пустая папка** | Разворачивает папку, в которой нет элементов | Папка разворачивается, но дочерние элементы не отображаются. Иконка отсутствует или серая. |
| **Элемент disabled** | Пытается развернуть/выбрать неактивный элемент | Элемент не реагирует на действия. Визуально — серый, неактивный. |
| **Элемент readOnly** | Пытается переместить элемент (Drag and Drop) | Перемещение невозможно. Элемент можно только выбрать и просмотреть. |
| **Поиск в дереве** | Вводит название папки в поле поиска | Дерево схлопывается, отображаются только найденные элементы и их родители. |

### Связанные тест-кейсы
- TC-TreeView-001, TC-TreeView-002 (разворачивание/сворачивание)
- TC-TreeView-004 (иерархия)
- TC-TreeView-006 (пустая папка)
- TC-TreeView-007 (выбор элемента)
- TC-TreeView-008 (открытие ФИ)
- TC-TreeView-011, TC-TreeView-012 (disabled/readOnly)
- TC-TreeView-014 (поиск)

## Сценарий 3: Добавление связанного элемента через View picker

**ID:** SCEN-003  
**Приоритет:** High  
**Компоненты:** View picker, View display

### Описание
Пользователь создает новый документ и добавляет к нему связанные элементы (например, подрядчиков, материалы, файлы) через поле выбора.

### Предусловия
- Пользователь авторизован в системе.
- Открыта форма создания/редактирования документа.
- В форме есть поле View picker для выбора связанных элементов.
- В системе есть минимум 10 элементов, доступных для выбора.

### Основной поток (Happy Path)
| Шаг | Действие пользователя | Ожидаемый результат системы |
|-----|----------------------|----------------------------|
| 1 | Нажимает кнопку "Выбрать" в поле View picker | Открывается модальное окно со списком доступных элементов (ListView). |
| 2 | Вводит в поле поиска название элемента | Список фильтруется, отображаются только подходящие элементы. |
| 3 | Выбирает один элемент (клик по строке) | Элемент подсвечивается как выбранный. |
| 4 | Нажимает кнопку "Применить" | Модальное окно закрывается. В поле View picker отображается выбранный элемент (название, код). |
| 5 | В поле View display видит добавленный элемент | Связанный элемент отображается в списке рядом с основным документом. |

### Альтернативные потоки
| Сценарий | Действие пользователя | Ожидаемый результат |
|----------|----------------------|---------------------|
| **Отмена выбора** | Нажимает "Отмена" в модальном окне | Модальное окно закрывается. Поле View picker остаётся пустым или в прежнем состоянии. |
| **Очистка поля** | Нажимает крестик в поле View picker | Выбранный элемент удаляется из поля. |
| **Выбор нескольких элементов** | Выбирает несколько элементов в модальном окне (если разрешено) | После применения все выбранные элементы отображаются в поле View picker. |
| **Обязательное поле** | Пытается сохранить форму, не заполнив View picker | Отображается сообщение об ошибке: "Это поле обязательно для заполнения". |
| **Режим readOnly** | Открывает форму с View picker в режиме только для чтения | Поле отображает выбранный элемент, но кнопка выбора неактивна или отсутствует. |

### Связанные тест-кейсы
- TC-ViewPicker-001 (открытие модального окна)
- TC-ViewPicker-002 (поиск)
- TC-ViewPicker-003 (выбор одного)
- TC-ViewPicker-004 (выбор нескольких)
- TC-ViewPicker-005 (очистка)
- TC-ViewPicker-007 (обязательность)
- TC-ViewPicker-008 (readOnly)
- TC-ViewDisplay-001, TC-ViewDisplay-004 (отображение и обновление)

## Сценарий 4: Массовые операции с документами

**ID:** SCEN-004  
**Приоритет:** Medium  
**Компоненты:** ListView

### Описание
Пользователь выделяет несколько документов и выполняет над ними массовое действие (например, удаление, изменение статуса, экспорт).

### Предусловия
- Пользователь авторизован в системе.
- Открыт ListView с документами.
- В системе есть минимум 5 документов.

### Основной поток (Happy Path)
| Шаг | Действие пользователя | Ожидаемый результат системы |
|-----|----------------------|----------------------------|
| 1 | Кликает по чекбоксам трёх документов | Три документа выделяются. Внизу появляется меню действий. |
| 2 | В меню действий выбирает "Изменить статус" | Открывается модальное окно с выбором нового статуса. |
| 3 | Выбирает статус "В работе" и нажимает "Применить" | У всех трёх документов статус меняется на "В работе". Модальное окно закрывается. |
| 4 | В списке проверяет статусы выбранных документов | У всех трёх документов отображается новый статус (чипс обновился). Выделение снимается, меню действий пропадает. |

### Альтернативные потоки
| Сценарий | Действие пользователя | Ожидаемый результат |
|----------|----------------------|---------------------|
| **Выбрать все** | Нажимает кнопку "Выбрать все" в нижнем меню | Выделяются все документы на текущей странице (или во всём списке). |
| **Снять все** | Нажимает кнопку "Снять все" | Выделение со всех документов снимается. Меню действий пропадает. |
| **Снятие выделения кликом вне списка** | Кликает на пустую область списка | Выделение снимается, меню действий пропадает. |
| **Массовое удаление** | Выделяет документы и выбирает "Удалить" | Отображается диалог подтверждения. При подтверждении документы удаляются. |
| **Отсутствие действий при ПКМ** | Кликает ПКМ по выделенному документу | Меню ПКМ не появляется (или оно ограничено, чтобы не путать пользователя). |

### Связанные тест-кейсы
- TC-ListView-010 (выделение чекбоксом)
- TC-ListView-011 (отсутствие меню при ПКМ)
- TC-ListView-012, TC-ListView-013 (Выбрать все / Снять все)
- TC-ListView-014, TC-ListView-015 (снятие выделения)
- TC-ListView-023 (действия из нижнего меню)
